## 2. バックエンドの核

- [ ] Honoの案件作成・取得・メッセージAPIを作る
- [ ] HttpOnly cookieによる案件所有者の隔離とOrigin検証を作る
- [ ] 案件DOへ状態を保存し、Hibernation WebSocketで同期する
- [ ] commandIdによる重複排除とrevisionによる競合拒否を作る
- [ ] D1へ架空会社・商品・注文・交換規則と案件一覧を用意する
- [ ] 注文番号と閲覧コードを照合し、交換条件を実データから返す
- [ ] 社員依頼を作り、引き受けと回答を記録する
- [ ] 社員認証未設定時は社員APIを閉じる
- [ ] 同時引き受け、二重回答、案件間漏洩、再接続を試験する
- [ ] 待機中のinterval、polling、alarm予約を作らない

受入条件は、来訪者の案件から注文調査と社員回答までが保存され、再取得で同じ状態を読めること。
社員回答後のAI再開待ちと、実際のAI再開を区別する。

## 3. 業務AIと音声

- [ ] OpenAIへの接続処理をWorker側に置く
- [ ] 配布キーの設定不足とプロバイダー失敗を明示的なエラーにする
- [ ] Agents sessionと案件の対応をサーバーへ保存する
- [ ] 保存した用件と業務ルールからAgentsの仕事を始め、社員回答を同じsessionへ戻す
- [ ] 署名Webhookを検証し、最新sessionとturnの結果を読む
- [ ] GPT-LiveのWebRTC sessionを作り、sidebandで委譲を受ける
- [ ] Live委譲のIDと案件revisionを結びつけ、確認済みの結果だけを返す
- [ ] 通話終了時に外向きWebSocketを閉じる
- [ ] 配布プロジェクトでGPT-LiveとAgents APIを実際に接続する

受入条件は、会話を続けながら調査し、社員回答後に案内が続くこと。
モデルのidleと業務の成功を同一視しない。
